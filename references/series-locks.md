# 系列母版锁定规则

## 证据基线

五张既有成片全部为 1024×1536、2:3 竖卡。它们跨越 WATERSIDE、NIGHT MODE、RED DATE、DAY MODE、GREEN WALK，但卡面几何、人物呈现和 UI 语言高度一致。以下规则是不可漂移的系列母版，不是可选建议。

## CANVAS_LOCK

- 固定母卡尺寸为 1024×1536 px，比例 2:3，sRGB。
- 完整卡框必须触及并包围四边；不得做无框海报、横图、方图或 4:5 裁切。
- 平台要求 9:16 时，把完整 2:3 卡居中嵌入 1080×1920 外层画布，用主题色或像素纹理补边，不裁掉标题、边框或底栏。

## FRAME_GEOMETRY_LOCK

- 左右装饰轨各约占画布宽度 3%–8%。
- 顶部标题与状态区约占画布高度 8%–16%。
- 底部年份、条码、徽章与控制区约占画布高度 8%–13%。
- 中央叙事场景约占画布宽度 84%–94%、高度 72%–82%。
- 四角必须有主题化装饰锚点：花、心、宝石、贝壳、链条或星形；同一卡内左右呼应。
- 顶部主题牌必须与左右轨发生明确连接，左右轨必须一直延伸并连接到底栏；四角锚点负责遮住接缝，形成完整闭环。
- 四条边全部落在画布安全区内，最外侧仍保留 2–8 px 的连续像素轮廓；禁止任何一边被裁切、淡出或被场景覆盖。
- 左右轨至少各有两个可辨识的重复节点，底栏必须同时容纳年份/编号、中央徽章和条码/控制位，不得退化为一条细线。
- 主题可改变装饰材料与颜色，但标题牌、双侧轨、四角锚点、中央场景、底栏的层级与闭环关系不能消失。
- 生成后单独导出全尺寸透明 `frame-ui.png`：中央场景透明，完整框体、标题与 UI 保持原像素位置；若无法无损分离，重新生成动画母版。

## FRAME_REFERENCE_GRAMMAR

将既有 RED DATE、WATERSIDE、NIGHT MODE 等成片只作为结构语法参考，不复制其人物或具体素材：

- RED DATE 型：顶部大标题牌 + 花/心四角 + 垂坠侧轨 + 底部年份/心形/条码三段式底栏。
- WATERSIDE 型：顶部标题牌 + 蓝白花角 + 细珠宝侧轨 + 底部花簇与心形徽章闭合。
- NIGHT MODE 型：顶部科技标题条 + 黑金链条侧轨 + 发光宝石节点 + 厚重控制台底栏。
- 新主题至少选择一种骨架，再替换主题材质；不得把元素散落在四周却缺少连续承重边框。

## FRAME_FX_LOCK

- 静态框体逐帧锁定；动效只来自独立 `FRAME_FX` 叠加层。
- 可动点限定为角部宝石、侧轨灯珠、底部徽章、音乐图标的局部星芒或光环；标题文字、年份、LOOK、ONLINE 与条码本体保持不动。
- 默认至少设置两个错峰局部闪光，且至少一个为宝石星芒；同时激活 1–3 个点，错峰环绕四边，星芒半径 4–10 px，光环外扩 3–8 px，首尾强度为零。
- 禁止整圈边框缩放、漂移、扭曲、色相轮转、全边频闪或让粒子穿进中央人物区。

## TITLE_AND_UI_LOCK

- 顶部中央放 1 个大写英文主题标题，使用粗像素衬线或早期游戏 UI 字体。
- 卡面必须同时出现：绿色 ONLINE 状态、LOOK 编号、2004/2005 年份、音乐图标、底部条码。
- ONLINE、LOOK、年份可在顶部或底部互换位置，但必须处于卡框 UI 区，不得漂入人物脸部或场景中央。
- 所有文字保持水平、清楚、拼写正确；禁止伪字、乱码、变形字和现代无衬线极简排版。

## CHARACTER_SCALE_LOCK

- 使用单个成年、修长、半写实换装人偶，不使用儿童比例、Q 版、大头娃娃或写实照片拼贴。
- 站立人物总高约占画布高度 68%–75%；坐姿约 60%–66%。
- 头顶通常位于画布高度 12%–24%，脚或鞋底位于 84%–91%，并始终高于底部 UI。
- 人物最宽处约占画布宽度 28%–48%；视觉中心保持在画布水平中线附近，可因姿态偏移但不可贴边。
- 头身比默认锁定 8.0–8.5 头身；头部高度约为完整身体高度的 11.5%–12.5%。7.5 头身仅限用户明确要求更可爱时使用；默认拒绝偏幼态的大头、短躯干和 Q 版脸。
- 完整显示头发轮廓、双手、腿与鞋；除坐姿被场景物自然遮挡外，不裁手脚。

## CHARACTER_STYLE_LOCK

- 风格为早期 QQ秀/网页换装游戏的高精细像素半写实：身体结构接近真人，脸部柔和理想化，边缘和材质保留像素簇与抖色。
- 五官采用年轻成人面板：椭圆或轻 V 形脸、略放大的杏眼、小鼻、小嘴、柔和腮红；不得转成日漫大眼或照片级真人脸。
- 头发有清楚发束与高光，但轮廓仍是像素边缘；服装有可读褶皱、面料和配饰，不做现代扁平插画。
- 姿态保持换装展示逻辑：正面或 10°–30° 轻侧身、重心转移、一只手做简单动作；禁止夸张扭腰和复杂透视手势。

## SCENE_AND_PALETTE_LOCK

- 背景必须是完整主题场景而非纯色：水岸、树林、城市夜景、室内或街道，并具备前景、中景、远景。
- 人物与背景使用统一像素密度；禁止把真人抠图贴在像素背景上。
- 每张卡由 2–3 个主色统领边框、UI 与场景；WATERSIDE 可用蓝白，NIGHT MODE 用黑蓝，RED DATE 用红金，DAY/GREEN 用青白或绿金。
- 背景细节丰富，但人物脸、服装轮廓和文字优先级最高。

## PET_SCALE_LOCK

- 每张卡固定 1 个 PET_LAYER，位于人物脚边或底部一侧，视线可朝人物。
- 普通犬、猫、兔、熊默认占画布高度 10%–16%，硬下限为 10%；鸟或小精灵约 7%–11%；普通宠物约为人物高度的 18%–28%。
- 宠物不得遮挡人物脚、底栏、年份或条码，不得放大成第二主角。
- 宠物像素密度、光向和色温必须与人物及场景一致。
- 深色宠物不得埋入同色暗背景，必须用轮廓光、浅色接触影或位置错开形成清晰剪影；在 512×768 预览中应一眼识别物种与朝向。
- PET 主动作必须由局部关节/轮廓变化并独立验收：默认锁定小白狗身体与四脚，只让身体后层尾巴围绕尾根连续摆动 8–24 px，并由身体前层覆盖连接处。兔子只有母版生成阶段同步获得原生独立耳层且 72 帧碎片率不超过 3% 时才使用；禁止从扁平兔子裁耳。sprite 仅作备选，至少 3 个不同轮廓且 24 fps 下 `frame_hold<=3`。普通宠物根节点位移不超过 6 px、整体旋转不超过 2.5°。禁止同一贴纸整块跳动，边框、灯光和环境变化不得计入宠物动作。

## PIXEL_MATERIAL_LOCK

- 使用高精细 2000 年代网页游戏像素画：可见 1–3 px 像素簇、受控抖色、硬边高光和游戏 UI 质感。
- 禁止平滑矢量边、现代 3D 渲染、油画厚涂、纯摄影背景或模糊滤镜覆盖像素结构。
- 输出前在 100% 比例检查人物边缘、文字、条码、宝石、花朵和宠物是否属于同一像素世界。

## 拒绝条件

出现以下任一项即重做：尺寸不是 1024×1536；卡框缺边、缺角、断轨、被裁或底栏缺失；人物非完整全身；站立人物低于 68% 或高于 75%；默认人物低于 8 头身或明显 Q 版；缺少宠物；普通宠物只有整块根节点跳动、断耳/断尾/漂浮碎片或阶梯式 sprite；发梢整束刚体旋转；用户未明确要求却出现动态落叶；无水场景出现矩形背景扭曲；缺少至少两个错峰卡框闪点或缺少宝石星芒；缺少 ONLINE、LOOK、年份、音乐图标或条码；背景为空；人物与背景像素密度不一致；标题拼写错误；整圈边框发生缩放、漂移或变形。
